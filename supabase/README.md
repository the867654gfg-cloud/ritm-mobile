# Миграции Supabase

Перед развёртыванием проверьте историю миграций подключённого проекта. Применяйте только отсутствующие миграции в порядке имён файлов. Архив рассчитан на существующую базу «Ритм» с исходными таблицами каталога.

| Файл | Что делает |
|---|---|
| `…01_auth_profiles_and_avatars` | профили, автосоздание профиля при регистрации, проверка занятости имени, бакет `avatars` |
| `…02_secure_tracks_playlists_and_storage` | включает RLS у `tracks`, убирает политики «разрешить всем» у плейлистов и хранилища |
| `…03_lock_down_handle_new_user` | закрывает служебную функцию от вызова через API |
| `…04_allow_owner_to_delete_own_track_files` | владелец трека может удалять файлы своих треков |
| `…05_cascade_track_references` | удаление трека убирает его из избранного и плейлистов |
| `…user_library_and_track_stats` | облачная медиатека и счётчики |
| `…ritm_product_improvements` | страницы авторов, приватные черновики, ссылки на плейлисты, жалобы и статистика по дням |

После установки зависимостей задайте в окружении сборки `EXPO_PUBLIC_SUPABASE_URL` и `EXPO_PUBLIC_SUPABASE_ANON_KEY` (публичный клиентский ключ). Проверьте `npm run web` или соберите веб-версию через `npx expo export --platform web`. В `app.json` задан путь `/ritm-mobile` для GitHub Pages. При размещении в корне домена уберите `experiments.baseUrl` перед сборкой. Размещение должно использовать HTTPS для офлайн-режима.

В настройках Auth проверьте ограничения на регистрацию и вход и доступность защиты от скомпрометированных паролей. Эти параметры проекта задаются отдельно. Жалобы администратора доступны в таблице `ritm_reports`. Счётчики за день и неделю накапливаются с момента применения миграции. Старые даты публикации остаются неизвестными.

Новые изменения базы добавляйте новыми файлами с бо́льшим номером. Уже применённые файлы не редактируйте.

Очистка лишних файлов из хранилища: `node scripts/cleanup-orphan-files.mjs` (инструкция в начале файла).
